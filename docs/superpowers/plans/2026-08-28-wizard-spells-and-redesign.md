# Wizard — Magias, Itens dedicados e reestruturação visual Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a real Magias (spell) system to `CharacterWizard`, and restructure it into 6 icon-driven steps with dedicated Itens and Magias sections, so it reads like a real RPG character creator instead of a form.

**Architecture:** Two new DB tables (`spells`, `class_spells`) plus `icon`/`known_spell_ids`/`custom_items` columns, all following the exact patterns already established by `tools`/`origins` in this codebase. `CharacterWizard.tsx` is restructured task-by-task: first icons on existing cards, then the equipment/tool UI is extracted into its own "Itens" step, then a brand-new "Magias" step is added. Nothing is hardcoded — the wizard reads whichever classes/species/origins/spells exist in the DB, exactly like the original wizard (etapa 11).

**Tech Stack:** Next.js 16 Route Handlers, Drizzle ORM + Postgres, React 19, Mantine 9, TanStack Query, `@iconify/react`.

**Spec:** `docs/superpowers/specs/2026-08-28-wizard-spells-and-redesign-design.md`

## Global Constraints

- All API responses use the `{ success, message: {pt-br,es-mx,en-us}, data }` envelope, snake_case keys — see `.claude/rules/api-response-format.md`.
- Every `.tsx` file follows `.claude/rules/tsx-patterns.md`: 2+ attributes on a tag → one per line; text content of a tag on its own line; blank line between JSX siblings.
- `known_spell_ids` and `custom_items` are Mestre-only — **never** appear in `ICharacterDisplay` or in the `?view=display` payload of `GET /api/tables/[code]`. Same rule as `class_id`/`attributes` (see `.claude/rules/table-concept.md` seção 2/3).
- `GET /api/spells`, `/api/classes`, `/api/species`, `/api/origins`, `/api/tools` are all system content — no Mestre cookie check.
- Migrations in this repo often get silently skipped by `npm run db:migrate` (drizzle-kit compares `MAX(created_at)`, not per-file hash). If that happens: apply the `.sql` file directly via `docker exec -i storyweaver-postgres psql -U postgres -d storyweaver < path/to/migration.sql`, then compute its sha256 (`node -e "console.log(require('crypto').createHash('sha256').update(require('fs').readFileSync('db/migrations/000N_xxx.sql')).digest('hex'))"`) and `INSERT INTO drizzle.__drizzle_migrations (hash, created_at) VALUES ('<hash>', <journal's "when" value from db/migrations/meta/_journal.json>)`.
- Verification at the end of every task: `npx tsc --noEmit` and `npm run lint` must be clean — zero new errors, and exactly the same 4 pre-existing warnings (`locales/pt-br.ts`, `tailwind.config.mjs`, 2× `no-img-element` in `DisplayToken.tsx`/`MasterToken.tsx`). Do not add new warnings.
- The dev server runs on the host via `next dev -p 3002` (Turbopack + Windows bind-mount inside Docker doesn't work) — Postgres runs in `storyweaver-postgres` via `docker-compose.local.yml`, already up.

import { classes } from './classes';

// Join N:N entre classes e magias, com o ciclo em que a magia é conjurável

- [ ] **Step 1: Create `app/api/spells/route.ts`**

```ts
import { db } from '@/libs/db';
import { spells, classSpells } from '@/db/schema';
import { eq } from 'drizzle-orm';
import { NextResponse } from 'next/server';

// Lista magias — conteúdo de sistema, sem checagem de Mestre (mesmo padrão
// de /api/classes, /api/tools). Sem ?class_id, devolve o catálogo completo
// (ISpell[], usado pelo modal "Ver Magias"). Com ?class_id, devolve
// IClassSpell[] (magia + ciclo) só das magias daquela classe, ordenadas por
// ciclo e depois por nome — é o que a etapa Magias do wizard consome.
export async function GET(request: Request) {
  try {
    const classIdParam = new URL(request.url).searchParams.get('class_id');

    if (!classIdParam) {
      const rows = await db.select().from(spells).orderBy(spells.name);

      return NextResponse.json({
        success: true,
        message: { 'pt-br': 'Operação realizada com sucesso.', 'es-mx': 'Operación realizada con éxito.', 'en-us': 'Operation completed successfully.' },
        data: rows,
      });
    }

    const classId = Number(classIdParam);

    const rows = await db
      .select({ spell: spells, cycle: classSpells.cycle })
      .from(classSpells)
      .innerJoin(spells, eq(classSpells.spell_id, spells.id))
      .where(eq(classSpells.class_id, classId))
      .orderBy(classSpells.cycle, spells.name);

    return NextResponse.json({
      success: true,
      message: { 'pt-br': 'Operação realizada com sucesso.', 'es-mx': 'Operación realizada con éxito.', 'en-us': 'Operation completed successfully.' },
      data: rows,
    });
  } catch (e) {
    console.error(e);

    return NextResponse.json({ success: false, message: { 'pt-br': 'Erro ao listar as magias.', 'es-mx': 'Error al listar los hechizos.', 'en-us': 'Error listing spells.' }, data: null }, { status: 500 });
  }
}
```

    // (read pages 41-58 of "Contos e Cantos de Vilgard.pdf" for the remaining ~58 entries).
  ];

  await db.insert(spells).values(SPELL_CATALOG);
  console.log(`${SPELL_CATALOG.length} magias inseridas.`);

  const spellRows = await db.select({ id: spells.id, name: spells.name }).from(spells);
  const classRows = await db.select({ id: classes.id, name: classes.name }).from(classes);

  const classSpellRows: { class_id: number; spell_id: number; cycle: string }[] = [];

  for (const [className, lists] of Object.entries(SPELL_LISTS)) {
    const classRow = classRows.find((c) => c.name === className);

    if (!classRow) {
      console.log(`seedSpells: classe "${className}" não encontrada, pulando.`);
      continue;
    }

    const cycles: [string, string[]][] = [['truque', lists.truque], ['1', lists.c1], ['2', lists.c2]];

    for (const [cycle, names] of cycles) {
      for (const name of names) {
        const spellRow = spellRows.find((s) => s.name === name);
